01 / START

The 90-second mental model

Jira is the specification. Archon decomposes it into child stories, works in an isolated branch, verifies the result through code and browser evidence, then publishes exactly once.

The factory, not just the model

The model writes code. The workflow supplies the production system around it: context, isolation, risk classification, tests, independent reviewers, constrained git operations, and a feedback loop.

1Provide the ticket

Start the workflow with a Jira key. Archon fetches the canonical ticket fields and acceptance criteria.

2Let the DAG run

Archon creates child stories, syncs with main, explores the interfaces, implements, tests, and convenes QA.

3Review the evidence

The PR appears only after QA clears. Jira receives the PR URL and calibrated completion report.

bun packages/cli/src/cli.ts workflow run archon-ralph-dag \
  --cwd /path/to/product-repo \
  --branch SAP-3560-voice-health \
  "SAP-3560"

03 / PAPER

How it aligns with “The New SDLC With Vibe Coding”

The white paper’s central claim is that production quality comes from the harness around the model. Ralph implements that claim as executable workflow policy.

01

Factory model

The developer designs the production line; agents produce code; gates verify it. Ralph makes the assembly line explicit as a DAG.

02

Context engineering

Jira, repository rules, interface catalogs, risk briefs, and prior lessons are loaded where they are needed, not blindly everywhere.

03

Harness engineering

Worktrees, bounded tools, git hooks, test runners, browser probes, specialist handoffs, and logs surround the model with enforceable constraints.

04

Tests plus evals

Tests verify deterministic behavior. The QA panel, architecture review, and devil’s advocate evaluate non-deterministic quality and intent. The browser contract is not yet a full sentinel-data proof.

05

Trajectory evaluation

The implementation emits a trajectory record. The architecture audit checks whether component reads, builds, and explicit staging actually happened.

06

Continuous quality flywheel

Findings are appended to home-scoped lessons. Future exploration loads those failures as dynamic context so mistakes compound into safeguards.

07

The 80% problem

A questionable verdict triggers a structured stuck diagnosis: root cause, minimal human intervention, and a reusable lesson.

08

Orchestrator mode

Specialists operate asynchronously with narrow roles. The implementer never serves as its own final verifier.

“The developer’s primary output is not code — it’s the system that produces code.”
The New SDLC With Vibe Coding, “The factory model,” May 2026
04 / SAFETY

The guardrails that matter most

These controls prevent the recurring failure classes that motivated the workflow: wrong scope, false-green UI tests, assumptions about component APIs, and premature publication.

Source control

Product files only

Explicit staging, blocked broad-add patterns, forbidden file classes, and a final scope check prevent workflow state, docs, images, and unrelated edits from reaching the PR.

Architecture

Read before write

The Explorer catalogs real component signatures, rendered children, and context dependencies. The auditor independently traces no-op props and interface growth.

Evidence

No silent skip

Missing browser configuration is a failure. The present gate requires content-oriented assertions, but a full known-sentinel, empty-state, console, and network contract remains to be implemented.

Independence

Three-domain panel

Frontend, code, and architecture reviewers each synthesize deterministic evidence and add domain judgment. One Not-happy result blocks publication.

Risk

U × I classification

Every child story records uncertainty, impact, risk score, architecture trigger, and named interface seam. High-risk changes receive stricter review.

Publication

One push point

The remote branch and PR are created only after tests, browser evidence, architecture audit, scope check, panel synthesis, and disconfirmation review.

05 / OPERATE

Treat the workflow as a governed production process. Start with a well-formed ticket, watch gate outputs rather than prose confidence, and intervene only when the workflow presents a concrete escalation.

06 / GAPS

Current limits and next hardening steps

Ralph is aligned with the paper’s harness model, but several controls are still partial. These are operational gaps, not reasons to ignore the evidence already produced.

Current controlWhat it proves todayWhat it does not yet proveRecommended hardening
check-environmentRequired tools exist and the baseline package can build.Services are live, containers are not crash-looping, and the exact database/index is fresh and non-empty.Add project-declared readiness and data-truth commands, including two-sample restart checks.
visual-qaA Playwright suite exists, runs, and contains content-oriented assertions.A seeded known value is visible, the empty state is absent, and no console or HTTP ≥400 errors occurred.Adopt a standard golden-path fixture contract and shared Playwright instrumentation.
Trajectory auditThe implementer reports required reads, builds, and staging commands.The report matches the actual tool-call log.Derive trajectory facts from workflow events or provider tool traces instead of self-report.
QA remediation loopAny Not-happy, unresolved top fix, incomplete coverage, or questionable devil verdict blocks publication.The workflow does not yet route every blocked verdict into a fresh corrective implementer automatically.Add a bounded correction loop that preserves reviewer independence and reruns the same gates.
append-lessonsSuccessful runs can persist review findings for future exploration.Runs that fail before the report node do not append lessons.Use a terminal hook or failure branch that records lessons for every terminal status.
Jira child creationStories are mapped into child tickets with risk and seam context.Retry idempotency and duplicate prevention are not transactional guarantees.Store a deterministic story key/label and reconcile before creating a child.
07 / LIMITS

What remains human

Archon reduces review effort; it does not remove accountability. Architecture trade-offs, ambiguous product intent, and deployment approval remain human decisions.

Read the report as calibrated evidence

Deterministic gate results are verified facts. Agent reviews are reported facts until reproduced. A devil’s-advocate conclusion is a hypothesis. The report labels these separately so confidence does not outrun evidence.
